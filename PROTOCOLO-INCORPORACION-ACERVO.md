# Protocolo de incorporación del acervo histórico real

## Propósito y alcance

Este protocolo establece el procedimiento uniforme para recibir, describir, conservar y relacionar materiales reales que se incorporen posteriormente al acervo. Aplica a documentos, fotografías, fuentes orales, bibliografía y cualquier otro material admitido por las áreas ya existentes. No autoriza por sí mismo la publicación, reproducción ni interpretación de una fuente.

Se aplica junto con la [Estructura técnica y trazabilidad del acervo](ESTRUCTURA-ACERVO.md) y con los criterios de catalogación de cada área. Si un criterio específico del área exige un campo adicional, debe conservarse sin reemplazar las reglas de este protocolo.

## 1. Recepción de una fuente

Al recibir una fuente, abra un registro de recepción y consigne, como mínimo:

- **Qué es:** identificación o descripción objetiva del material, sin atribuir hechos que no estén documentados.
- **Quién la proporciona:** persona, institución o medio de entrega, únicamente cuando ese dato pueda registrarse.
- **Procedencia declarada:** origen o información de procedencia comunicada al momento de la recepción.
- **Fecha de recepción:** fecha en la que el acervo recibe o localiza el material.
- **Formato:** soporte o formato del objeto o archivo recibido.
- **Ubicación:** localizador físico, digital o referencia de acceso conocida.
- **Estado de conservación:** condición observable del objeto, cuando corresponda.
- **Restricciones de uso:** condiciones comunicadas o documentadas para consulta, reproducción o publicación, cuando existan.
- **Información desconocida:** cada dato no disponible debe registrarse como `desconocido` o dejarse sin completar según lo permita la ficha del área. No se sustituye por una estimación, una fecha supuesta ni otro dato inferido.

La recepción acredita que un material fue recibido o localizado; no acredita su autenticidad, exactitud, titularidad de derechos ni procedencia.

## 2. Identificación y asignación de ID

Antes de crear un registro, revise si la pieza ya tiene ficha o si es un derivado de una fuente registrada. Asigne el ID correspondiente al área que describe la pieza, respetando las convenciones existentes:

| Área o registro | Convención existente |
| --- | --- |
| Documentos históricos | `DOC-aaaa-nnn` o `DOC-sf-nnn` si no hay fecha documentada. |
| Fuentes orales | `ORL-aaaa-nnn` o `ORL-sf-nnn` si no se conoce la fecha. |
| Fotografías | `FOT-aaaa-nnn` o `FOT-sf-nnn` si no se conoce la fecha. |
| Bibliografía | `BIB-nnn`. |
| Historia | `HIS-aaaa-nnn`. |
| Puerto Ceiba | `PCE-aaaa-nnn`. |
| Cronología | `CRO-aaaa-nnn` o `CRO-sf-nnn` si no se conoce el año. |
| Personajes | `PER-nnn`. |
| Monografía | `MON-nnn`. |
| Sitio web | `WEB-nnn`. |

No cree prefijos nuevos para copias, digitalizaciones, transcripciones, fichas, investigaciones, borradores o publicaciones web. Estos materiales se distinguen por su tipo, archivo, relación y historial de versiones, y deben enlazar el ID de la ficha de la fuente maestra. Cuando la fecha requerida por una convención no se conozca, aplique únicamente la variante `sf` ya prevista por esa área; no invente una fecha.

## 3. Fuente maestra y vínculo de origen

La fuente maestra es el objeto original, archivo original recibido o archivo de máxima fidelidad conservado como referencia. Debe identificarse por su ID de ficha, conservar su nombre, extensión, procedencia y localizador conocidos, y mantenerse separada de los derivados.

- Una copia no sustituye al original.
- Una digitalización no debe confundirse con el objeto original.
- Una transcripción no sustituye al documento ni al testimonio.
- Una investigación no sustituye a la fuente que la sustenta.
- Una publicación web debe conservar el vínculo por ID con su fuente de origen y sus condiciones de uso.

Si la fuente maestra no está disponible, regístrelo como tal y conserve el localizador o la referencia disponible sin afirmar que se posee el original.

## 4. Digitalización

Para cada digitalización, registre su relación con el original y, cuando se conozcan, los siguientes datos:

- archivo maestro de digitalización;
- copia de trabajo, si se genera;
- formato del archivo;
- resolución u otra característica pertinente al tipo de material;
- fecha de digitalización;
- responsable de la digitalización;
- ID y localizador de la fuente original o maestra relacionada.

La copia de trabajo puede prepararse para consulta o edición, pero no reemplaza el archivo maestro de digitalización ni el objeto original. No se fijan especificaciones técnicas únicas: los datos técnicos se registran solo cuando correspondan al tipo de documento, imagen, audio, video u objeto.

## 5. Transcripción

Toda transcripción documental u oral debe indicar el ID de la fuente maestra, su archivo o localizador, responsable cuando se conozca, fecha de elaboración cuando se conozca y tipo de transcripción. Use una de estas denominaciones:

| Tipo | Uso |
| --- | --- |
| **Transcripción literal** | Representa el contenido procurando conservar sus formas expresivas y particularidades, con las intervenciones editoriales identificadas. |
| **Transcripción normalizada** | Adapta aspectos de presentación o escritura; debe indicar qué clase de normalización se aplicó. |
| **Transcripción parcial** | Reproduce solo una parte identificada de la fuente; debe delimitar el alcance. |
| **Texto editorial derivado** | Resume, adapta, interpreta o reorganiza información; no se presenta como transcripción. |

Una transcripción debe presentarse siempre como material derivado, nunca como si fuera la fuente original. Las omisiones, marcas de ilegibilidad, notas editoriales y decisiones de normalización deben distinguirse del contenido de la fuente.

## 6. Estados de verificación

El registro debe tener un único estado de trabajo vigente. Se emplean los siguientes estados:

| Estado | Significado |
| --- | --- |
| **recibido** | Material o referencia ingresado; aún no implica catalogación ni comprobación. |
| **pendiente de catalogación** | Recibido y a la espera de descripción suficiente. |
| **catalogado** | Cuenta con ficha descriptiva; sus datos aún pueden requerir comprobación. |
| **en verificación** | Se están contrastando datos, procedencia, relaciones o restricciones. |
| **verificado** | Los aspectos indicados en la ficha fueron comprobados con evidencia registrada; no se aplica a información que dependa de una fuente no comprobada. |
| **requiere revisión** | Hay una duda, cambio, discrepancia o ausencia que necesita atención. |

El estado `verificado` no autoriza usos restringidos ni resuelve por sí solo la autenticidad, los derechos o todas las interpretaciones posibles. La ficha debe indicar qué se verificó y con qué registros relacionados.

## 7. Corroboración y discrepancias

Cuando varias fuentes se refieran al mismo acontecimiento, persona, lugar o documento, cree relaciones por ID sin fusionar ni reemplazar los registros. En la ficha o nota de relación, consigne:

- fuente principal, cuando se haya definido para ese uso;
- fuentes secundarias;
- coincidencias observadas;
- discrepancias observadas;
- información pendiente de corroboración.

No resuelva automáticamente una discrepancia ni cambie una fuente para ajustarla a otra. Mantenga la discrepancia y su evidencia vinculada hasta que exista evidencia suficiente para documentar una resolución; esa decisión debe quedar registrada en el historial de versiones.

## 8. Procedencia y cadena de custodia

Registre la procedencia como información documentada o declarada, diferenciando —cuando se conozcan— origen, propietario, custodio, repositorio, donante, medio de adquisición y transferencias de custodia. La cadena de procedencia debe incluir únicamente los tramos que puedan documentarse o atribuirse claramente a una declaración.

No infiera procedencia a partir del contenido, del formato, de una copia o de la ubicación actual. Cuando la cadena sea incompleta, registre los tramos conocidos y marque el resto como `desconocido` o `pendiente de verificar`, según corresponda.

## 9. Derechos y restricciones

Para cada fuente y derivado, registre por separado, cuando corresponda:

- propietario o custodio;
- autorización de reproducción;
- restricciones de consulta, copia, difusión o publicación;
- condiciones de publicación, crédito o consentimiento;
- información desconocida.

La ausencia de una restricción registrada no equivale a autorización. No publique, reproduzca ni distribuya una fuente solo porque esté disponible, digitalizada o citada en una investigación. Los derivados y versiones web heredan las restricciones aplicables de la ficha maestra hasta que una autorización documentada indique otra cosa.

## 10. Control de versiones y tipos de registro

El historial de versiones debe distinguir el tipo y la relación de cada material:

| Tipo | Regla de identificación |
| --- | --- |
| Fuente original | Se identifica como fuente maestra u original y conserva su localizador. |
| Copia | Se identifica como copia y enlaza el ID de la fuente maestra. |
| Transcripción | Indica su tipo de transcripción y el ID de la fuente maestra. |
| Ficha | Describe el registro y no sustituye la fuente. |
| Investigación | Indica los IDs de las fuentes que la sustentan. |
| Borrador | Se identifica como texto de trabajo y enlaza sus fuentes. |
| Versión publicada | Indica que es versión de difusión, su fecha o estado de publicación cuando se conozca, y sus fuentes de origen. |

Registre en el historial de versiones la fecha, responsable cuando se conozca, cambio realizado y motivo o alcance. No sobrescriba un material maestro para incorporar una corrección editorial: cree o actualice el derivado correspondiente y mantenga el vínculo con la fuente.

## 11. Control de calidad antes de incorporar

Antes de considerar incorporada una fuente o derivado, compruebe:

- [ ] La pieza tiene identificación y descripción sin datos inferidos.
- [ ] La procedencia registrada distingue lo documentado de lo desconocido.
- [ ] Existe archivo maestro, objeto o localizador de referencia, o se indica expresamente que no está disponible.
- [ ] El ID cumple la convención del área y no duplica un registro existente.
- [ ] Las relaciones con fuente maestra, copias y derivados están registradas por ID o marcadas como pendientes.
- [ ] El estado de verificación corresponde a la evidencia disponible.
- [ ] Derechos, consentimiento y restricciones están registrados o figuran como desconocidos.
- [ ] El historial de versiones identifica los cambios y tipos de material.

## 12. Datos desconocidos, hipótesis y evidencia insuficiente

`Desconocido` no significa falso. La ausencia de información no debe rellenarse mediante una suposición, una estimación no identificada ni una coincidencia aparente. Si se formula una hipótesis de trabajo, debe etiquetarse explícitamente como hipótesis, indicar la evidencia disponible y conservar su estado pendiente de comprobación.

Las discrepancias deben preservarse con sus fuentes relacionadas hasta que exista evidencia suficiente para resolverlas. Una resolución documentada no elimina las versiones anteriores: se registra en el historial y mantiene los vínculos necesarios para reconstruir la decisión.

- **Fecha de recepción:**
